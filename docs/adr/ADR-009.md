# ADR-009: Capability Registry is Data-Driven

> **Status:** Accepted
> **Date:** 2026-07-13
> **Supersedes:** None
> **Superseded By:** None
> **Affects:** Governance Context, Domain Model

## Context

Different business categories have different feature requirements. A bakery needs a menu; a salon needs booking. Hard-coding feature availability per category makes it difficult to add new categories or override features.

## Decision

Capabilities are data-driven. Each Business has a set of Capabilities derived from its category and optionally overridden by the owner. Capabilities determine which features are available (menu, services, contact, hours, delivery, booking, reviews, inventory, payments, orders).

## Consequences

**Positive:**
- Easy to add new categories
- Easy to override features per business
- Feature availability is transparent
- No code changes needed for new capabilities

**Negative:**
- Capability logic must be maintained
- UI must handle all possible capability combinations
